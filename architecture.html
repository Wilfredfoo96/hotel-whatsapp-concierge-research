Architecture · Harper Boutique Hotel · WhatsApp concierge

One number. Three languages. No server of our own.

A guest messages the hotel on WhatsApp and gets the hotel's own words back in Malay, English or Chinese. Everything between those two moments is a Kapso workflow, one Cloudflare Worker, and a model that is only called when no ready-made reply fits. Tap any diagram to see it full size.

System context

Who talks to what.

Five things sit between the guest and an answer, and only one of them is ours to run.

One turn

Every message runs the same nine nodes.

The workflow is deliberately thin. It decides nothing itself: both decide nodes hand the question straight to the function and route on the edge label that comes back.

Inside the guard

Eight checks before anyone is answered.

The guard is where the cheap decisions live. Every check that can end a turn without a model call, or without a message at all, happens here in a fixed order.

Answering

The model is the last resort, not the first.

Most answers never reach Claude. The ones that do are chosen from a list the hotel wrote, and the model's own prose is checked before it can be sent.

Where the words come from

One file, three languages, built into the function.

A Kapso function is a single wrapped file with no imports, so the prompt and the replies are spliced into it at build time rather than loaded at runtime.

The watchdog

The one piece that must not live inside Kapso.

A dead-man ping that dies with the thing it watches is not a dead-man ping. harper-watch runs on a separate Cloudflare account, has no dependencies and no storage of its own, on purpose.

every 5 minutes

Webhook sink

Takes workflow.execution.handoff and conversation lifecycle events, opens and resolves escalations on harper-ops, and sends the PATCH that actually ends a handed-off execution. Nothing else releases one.

every 5 minutes

SLA sweep

Lists open escalations, pages at 15 minutes unacknowledged, dedupes for an hour and digests past three alerts, so a bad night is one message rather than forty.

every 5 minutes

Stuck-execution sweep

Branches on the last outbound staff message, never on how old the execution is — the correction that made it trustworthy in September.

unconditional, last

Dead man

Pings Healthchecks.io at the end of every sweep whatever else failed, so silence itself raises an alarm. A per-day execution fuse of 200 stands in for the spend cap Kapso does not offer.

Switches

Everything risky has an off switch.

on

ROUTER_ENABLED

Deleting the secret turns the fixed router off and sends taps and greetings to the model instead. That also turns the tap's cap exemption off, by design: if Claude answers the tap, the tap costs a slot.

on

PRESETS_ENABLED

Set to 0 and the bot falls back to the older knowledge-base prompt. Worth knowing before you use it: that prompt still carries the facts corrected in October, so the rollback is currently a step backwards.

off

AVAILABILITY_ENABLED

The GuestPro seam. Live availability needs working credentials and an inventory sync, so the bot sends every rate and availability question to the booking page instead.

never

A price in a message

There is no tool that can look up a price, so the model knows none. The gate enforces it on the way out, in all three languages, including numbers the guest quoted first.
